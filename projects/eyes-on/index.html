02 / OVERVIEW

카메라로 주변 시설을 파악해 음성으로 안내합니다

카메라와 음성을 통해 에스컬레이터·엘리베이터·개찰구 등의 상태를 안내하는 온디바이스 보행 보조 프로젝트입니다. 제한된 엣지 자원에서 질문에 필요한 시각 정보만 해석하고, 생성된 안내가 인지 결과와 충돌하지 않도록 설계했습니다.

MY SCOPE / TEAM CONTEXT

저는 VLM을 고르고, 장면을 판독하는 프롬프트와 안전 검증 규칙을 만들었습니다. VLM이 인지 결과를 받아 처리하도록 연결하는 작업에도 참여했습니다. 객체 탐지, 이동 방향 추정, 음성 처리와 전체 라우터 통합은 팀에서 함께 진행했습니다.

03 / PROBLEM & CONSTRAINTS

Problem & constraints

  1. Jetson에서 인지·음성 모듈과 VLM을 함께 실행해야 했습니다.
  2. 생성 모델이 탐지된 위치·방향과 다른 안내를 만들면 사용자가 혼동할 수 있었습니다.

05 / ENGINEERING DECISIONS

모델을 고르고 안내 문장을 검증했습니다

DECISION 01

Fit the edge budget

인지·음성 모듈과 함께 실행할 모델 선택

문제

큰 모델의 분석 능력만으로 선택하면 나머지 모듈이 메모리에 함께 올라가지 못했습니다.

선택

실제 모듈을 기동한 환경에서 모델을 비교해 SmolVLM-500M을 선정했습니다.

구현

추론 시간·메모리·상황 해석과 전체 파이프라인의 동시 실행 가능성을 함께 비교했습니다.

이유

프로젝트의 목적은 모델 벤치마크가 아니라 실제 장치에서의 안내였기 때문입니다.

결과

SmolVLM이 필요한 장면에서 판독 결과를 돌려주도록 연결했습니다.

범위와 한계

일부 장면의 분석 결과를 전체 모델 품질 우열로 일반화하지 않습니다.

DECISION 02

Grounded guidance

생성한 안내를 탐지 결과와 대조

문제

추측성 안내나 인지 결과와 다른 방향 설명이 나올 수 있었습니다.

선택

추가 판독이 필요한 경우에 VLM을 호출하고 Safety Validator를 통과시켰습니다.

구현

YOLO 위치·Optical Flow 방향과 충돌하면 인지 정보를 우선하고, 위험한 안전 판정 문장을 차단하거나 탐지 기반 문장으로 대체했습니다.

이유

일관된 근거를 가진 안내를 내보내기 위해서입니다.

결과

Rule·상태 판독·장면 설명의 역할과 생성 출력의 검증 경계를 분리했습니다.

범위와 한계

안전 검증 규칙이 실제 보행의 안전을 보장하거나 이동 결정을 대신하는 것은 아닙니다.

07 / LIMITATIONS & LESSONS

Limitations & lessons

응답 시간과 검증 환경

VLM 추론 자체는 약 0.62초였습니다. 음성 응답까지 걸리는 시간을 줄이려면 앞뒤 처리 구간도 함께 살펴야 합니다.

앞으로 개선할 점

반복 측정과 다양한 환경 평가, 지연 최적화 및 실제 사용자 검증이 필요합니다.
