OVERVIEW

카메라로 주변 시설을 파악해 음성으로 안내합니다

카메라와 음성을 통해 에스컬레이터·엘리베이터·개찰구 등의 상태를 안내하는 온디바이스 보행 보조 프로젝트입니다. 제한된 엣지 자원에서 질문에 필요한 시각 정보만 해석하고, 생성된 안내가 인지 결과와 충돌하지 않도록 설계했습니다.

MY SCOPE / TEAM CONTEXT

저는 VLM을 고르고, 장면을 판독하는 프롬프트와 안전 검증 규칙을 만들었습니다. VLM이 인지 결과를 받아 처리하도록 연결하는 작업에도 참여했습니다. 객체 탐지, 이동 방향 추정, 음성 처리와 전체 라우터 통합은 팀에서 함께 진행했습니다.

PROBLEM & CONSTRAINTS

문제와 제약

  1. Jetson에서 인지·음성 모듈과 VLM을 함께 실행해야 했습니다.
  2. 생성 모델이 탐지된 위치·방향과 다른 안내를 만들면 사용자가 혼동할 수 있었습니다.

ENGINEERING DECISIONS

모델을 고르고 안내 문장을 검증했습니다

Fit the edge budget

인지·음성 모듈과 함께 실행할 모델 선택

문제

보드의 공유 메모리 7.6GB 중 인지·음성 모듈을 띄운 뒤 VLM에 쓸 수 있는 여유는 3.1GB였습니다.

선택

실제 모듈을 기동한 환경에서 모델을 비교해 SmolVLM-500M을 선정했습니다.

구현

추론 시간과 메모리 사용량을 비교하고 다른 모듈을 함께 실행할 수 있는지 확인했습니다.

이유

모델 하나의 응답 속도만큼 인지와 음성 안내를 동시에 유지할 수 있는지가 중요했습니다.

결과

다른 모듈과 함께 실행할 수 있는 SmolVLM-500M을 채택했습니다. 개발 중 제가 담당한 VLM 추론 경로의 지연을 약 5초에서 약 2.7~2.9초로 줄였습니다.

범위와 한계

개인 개선 수치는 개발 당시의 근사치입니다. 아래 표에는 팀 최종 구성에서 기록한 모델별 추론 시간을 정리했습니다.

모델별 추론 시간과 동시 실행 조건2026.09.05 · Jetson Orin Nano · YOLO, Optical Flow, STT, TTS 구동 상태
모델추론 시간동시 실행
SmolVLM-500M Q80.62초가능 · 채택
Qwen3-VL-4B Q42.8초가능 · 여유 메모리 대부분 사용

0.62초는 추가 최적화가 반영된 팀 구성에서 기록한 모델 추론 시간입니다. 음성 응답까지 걸린 전체 시간은 검증 섹션에 따로 표시했습니다.

Grounded guidance

VLM은 화면을 읽어야 할 때만 호출하고, 탐지 결과와 충돌하는 출력은 안내하지 않습니다

문제

화면을 해석해야 하는 요청이 있는 반면, 탐지된 위치나 방향과 어긋나는 설명은 혼동을 줄 수 있었습니다.

선택

규칙으로 답할 수 있는 요청은 Rule 경로에서 처리하고, 화면 해석이 필요하면 VLM 상태 판독 또는 장면 설명 경로를 사용했습니다.

구현

vlm_scene은 객체가 탐지되지 않은 장면에서도 호출할 수 있습니다. 비교할 YOLO 위치나 Optical Flow 방향 정보가 있으면 VLM 출력과 대조하고, 충돌한 출력은 안내에 사용하지 않았습니다.

이유

화면을 읽는 기능은 유지하면서 확인된 인지 정보와 어긋나는 안내를 피하기 위해서입니다.

결과

Rule·상태 판독·장면 설명을 구분하고, 탐지 결과가 있는 경우에 출력의 위치·방향을 대조했습니다.

범위와 한계

객체가 감지되지 않은 장면에는 대조할 탐지 결과가 없을 수 있습니다.

VERIFICATION & RESULTS

검증과 결과

동시 실행

인지·음성 모듈을 구동한 상태에서 모델별 메모리와 추론 시간을 비교했습니다.

출력 충돌

비교할 인지 결과가 있을 때 안내의 위치·방향이 탐지 결과와 맞는지 확인했습니다.

전체 지연

2026년 9월 5일, Jetson Orin Nano에서 인지·음성 모듈과 VLM을 함께 실행한 상태로 측정했습니다. 팀 시스템의 VLM 경로는 음성 응답까지 약 3.07초가 걸려 목표인 3초를 넘었습니다.

LIMITATIONS & LESSONS

한계와 배운 점

응답 시간과 검증 환경

VLM 추론 시간을 줄였지만 음성 응답까지의 지연에는 앞뒤 처리 구간도 포함됩니다.

앞으로 개선할 점

반복 측정으로 전체 응답의 병목을 확인하고, 다양한 환경과 실제 사용자 조건에서 검증할 필요가 있습니다.
