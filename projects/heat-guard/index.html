Heat-Guard

폭염 속 근로자의 생체 신호를 측정하는 웨어러블 기기

PERIOD
2025.07–2025.11
ROLE
센서 데이터 수집·전송
TECHNOLOGIES
ESP32 · Arduino IDE · DS18B20 · MAX30102
개요문제와 제약구조기술적 결정검증과 결과한계와 배운 점
OVERVIEW

체온과 심박수를 측정하는 웨어러블

폭염 환경 근로자의 생체 신호를 수집해 위험 판단에 활용하는 웨어러블 프로젝트입니다. 저는 ESP32에서 체온, 심박수, 산소포화도를 읽고, 값이 비어 있거나 범위를 벗어났을 때 위험 판단 쪽으로 무엇을 보낼지 정했습니다.

MY SCOPE / TEAM CONTEXT

저는 센서값을 수집해 보내고, 제외한 값은 관리자 화면에서 오류로 볼 수 있게 했습니다. 팀원은 위험도 판정 알고리즘을 만들고 배터리를 골랐습니다. 기온과 습도는 외부 기상정보 API에서 가져왔습니다.

PROBLEM & CONSTRAINTS

문제와 제약

  1. 초기에는 센서에서 읽은 값을 그대로 보냈습니다. 이상값이나 누락값이 판단부에 들어가면 판단 로직이 오작동하거나 시스템이 멈췄습니다.
  2. 읽은 값을 조건 없이 계속 보내면 노트북(Gateway)에서 위험 판단에 필요한 값의 처리가 늦어졌습니다.

ENGINEERING DECISIONS

누락값을 표시하고 센서별 전송 주기를 조정했습니다

Validate at the source

센서값을 보내기 전에 확인

센서에서 튄 값도 그대로 위험 판단에 쓰일 수 있었습니다.

센서 입력 상태별 처리체온·심박수·산소포화도의 의학 참고치를 바탕으로 유효 범위를 정했습니다.
입력 상태처리 방식
유효 범위 안측정값을 정상값으로 전달
아직 수집 주기가 오지 않음직전값 유지
유효 범위 밖결측으로 표시해 전달하고 관리자 화면에서 오류 확인

판단부에서 뒤늦게 걸러내면 값을 사용하는 계층마다 같은 방어 코드가 필요합니다. 수집 단계에서 한 번 규칙을 적용하고, 받는 쪽이 정상값·직전값·결측을 구분할 수 있게 했습니다.

확인한 결과

정상값과 결측, 유지된 값을 구분하는 입력 흐름을 구성했습니다.

범위와 한계

유효 범위는 센서 입력을 검사하는 기준입니다. 의료기기 수준의 임상 검증은 별도로 필요합니다.

Sensor scheduling & delivery

센서마다 전송 주기를 다르게 설정

문제

센서값을 읽을 때마다 보내면 판단에 필요한 값의 처리가 늦어졌습니다.

선택

심박수·체온·산소포화도의 중요도에 따라 전송 주기를 각각 정했습니다.

구현

ESP32에서 보낼 센서값을 CSV로 묶어 Wi-Fi로 노트북(Gateway)에 전송했습니다.

이유

판단에 필요한 값은 제때 보내면서 불필요한 전송을 줄이기 위해서입니다.

결과

노트북(Gateway)에서 실행되는 판단부가 센서값을 받아 위험도를 계산하도록 연결했습니다.

범위와 한계

효율 개선율을 확인할 수 있는 측정 자료는 남아 있지 않습니다.

전송·오류 표시

OUTCOME

센서값을 보내기 전에 유효 범위를 검사하고, 범위를 벗어난 값은 결측으로 처리하도록 수정했습니다. 수정 후 오류값으로 인한 시스템 중단은 0건이었습니다.
