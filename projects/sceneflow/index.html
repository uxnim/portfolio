02 / OVERVIEW

이야기부터 숏폼 영상까지 만드는 서비스

캐릭터와 프롬프트를 골라 이야기, 이미지, 숏폼 영상을 만드는 해커톤 프로젝트입니다. 저는 같은 캐릭터 정보를 대사와 이미지 생성에 쓰고, 영상이 완성되기 전에도 진행 상태를 확인할 수 있게 백엔드를 구성했습니다.

MY SCOPE / TEAM CONTEXT

저는 FastAPI와 MySQL로 API를 만들고, AI로 대사와 이미지를 생성하는 기능을 맡았습니다. 팀은 프론트엔드와 영상 생성 흐름을 구현했습니다. 생성된 초안에서 사용자가 바꾸고 싶은 대사나 장면만 수정할 수 있도록 했습니다.

03 / PROBLEM & CONSTRAINTS

Problem & constraints

  1. 요청마다 캐릭터의 성격·말투·외형이 달라질 수 있었습니다.

05 / ENGINEERING DECISIONS

캐릭터 설정을 공유하고 생성 상태를 알렸습니다

DECISION 01

Consistent generation context

대사와 이미지에 같은 캐릭터 설정 사용

문제

프롬프트를 개별 수정하는 방식만으로는 반복 생성의 일관성을 유지하기 어려웠습니다.

선택

캐릭터 에셋과 프롬프트 템플릿을 생성 입력에 반영했습니다.

구현

대사와 이미지 생성에 필요한 캐릭터 정보를 연결하고 단계별 산출물을 다음 입력으로 넘겼습니다.

이유

생성 결과의 변동성을 입력 구조에서도 줄이기 위해서입니다.

결과

캐릭터 기반 스토리·이미지 생성 흐름을 구성했습니다.

범위와 한계

일관성 개선의 정량 평가 자료는 없으며 영상 품질에는 한계가 남았습니다.

DECISION 02

Visible processing states

생성 중에도 진행 상황 표시

문제

영상 생성에 시간이 오래 걸려 사용자를 생성 화면에 계속 머물게 할 수 없었습니다.

선택

WebSocket을 사용해 생성 화면에 머물러 기다리지 않아도 되도록 했습니다.

구현

Backend에서 단계별 입력·산출물을 나누어 진행 상황과 실패 위치를 구분하는 흐름을 설계했습니다.

이유

사용자가 영상이 생성되는 중인지, 중간에 실패했는지 알 수 있어야 했습니다.

결과

팀에서 콘텐츠를 생성하고, 완성한 결과를 관리하고 볼 수 있는 흐름을 구현했습니다.

범위와 한계

외부 생성 모델의 지연과 실패를 없앤 결과는 아닙니다.

07 / LIMITATIONS & LESSONS

Limitations & lessons

생성 품질과 편집 기능

영상의 세부 표현과 생성 속도에 한계가 있었고, 편집 기능은 초안의 일부 대사나 장면을 수정하는 범위였습니다.

앞으로 개선할 점

생성 실패 복구와 품질 평가 기준, 편집 기능을 추가 검증해야 합니다.
