02 / OVERVIEW

정합 결과가 같은 구간에서 흔들렸습니다

Robotics and AI Navigation Lab에서 이기종 LiDAR 정합과 LiDAR–Camera Calibration을 학습·실험했습니다. Velodyne과 Ouster의 정합 결과가 특정 구간에서 반복적으로 흔들리는 문제를 알고리즘 설정과 입력 환경을 함께 살피며 분석했습니다.

MY SCOPE / TEAM CONTEXT

학부연구생으로 Linux에서 C++로 ICP 정합을 실험하고 데이터를 다시 모으는 데 참여했습니다. 발표에서는 정합 이론과 재현 실험, 후속 실험 제안을 정리했습니다.

03 / PROBLEM & CONSTRAINTS

Problem & constraints

  2. 센서마다 타겟을 검출하는 특성이 달라 단일 조건으로 평가하기 어려웠습니다.

05 / ENGINEERING DECISIONS

설정값과 측정 환경을 따로 확인했습니다

DECISION 01

Reframe the problem

정합 결과와 원본 포인트 비교

문제

설정값 조정만으로 흔들리는 구간을 설명하지 못했습니다.

선택

원본 측정값과 주변 환경을 다시 관찰했습니다.

구현

주변의 반사가 강한 물체와 표적이 잘 구분되지 않는 것을 확인했습니다. 반사체가 적은 곳에서 데이터를 다시 모았습니다.

이유

문제를 최적화 파라미터에만 한정하면 측정 환경에서 생긴 오류를 놓치기 때문입니다.

결과

반사체가 적은 곳에서 다시 모은 데이터에서는 정합 결과가 흔들리는 구간이 줄었습니다.

범위와 한계

전후 오차를 수치로 비교한 자료는 남아 있지 않습니다.

DECISION 02

Target evaluation

체커보드 대신 쓸 표적 비교

문제

체커보드 대안이 모든 센서에서 더 잘 보인다는 보장은 없었습니다.

선택

ArUco를 더한 체커보드, RGB 색상을 적용한 표적, 원형 홀을 둔 표적을 각각 비교했습니다.

구현

센서별 검출 특성을 관찰하며 타겟 조건을 탐색했습니다.

이유

알고리즘의 입력이 되는 특징을 센서 관점에서 이해하기 위해서입니다.

결과

후속 실험에서 비교할 조건과 검출 특성을 정리했습니다.

범위와 한계

체커보드보다 성능이 나아지지는 않았습니다. 딥러닝으로 정합 결과를 보정하는 방법은 후속 과제로 제안했습니다.
