NAS Network Recovery

이사 후 끊긴 외부 SFTP 접속을 복구했습니다.

PERIOD
2022–
ROLE
개인 NAS 구성·장애 복구·운영
TECHNOLOGIES
Synology NAS · NAT · SFTP · Tailscale
개요문제와 제약구조기술적 결정검증과 결과한계와 배운 점
OVERVIEW

이사 후 끊긴 외부 SFTP 접속

개인 시놀로지 NAS를 외부에서 사용하던 중, 이사 후 이중 공유기 환경에서 SFTP 접속이 끊겼습니다. Tailscale로는 접속할 수 있어 NAS가 응답한다는 점을 먼저 확인했습니다. 두 공유기의 전달 설정을 다시 맞춰 외부 SFTP 접속을 복구했습니다.

개인 운영

2022년에 집에 NAS를 직접 설치했고, 전역 후부터 본격적으로 관리했습니다. 웹 검색과 AI의 도움으로 이중 공유기의 동작을 파악했고, 설정을 바꾸고 접속을 확인하는 일은 직접 했습니다.

PROBLEM & CONSTRAINTS

Tailscale은 연결됐지만 SFTP는 끊겼습니다

BEFORE / 처음 시도

개인 공유기의 전달 설정만 점검

AFTER / 개선 흐름

통신사 공유기 → 개인 공유기 → NAS 경로 연결

  1. 통신사 공유기 아래에 개인 공유기가 연결됐지만 처음에는 개인 공유기의 전달 설정만 바꿨습니다.
  2. Tailscale과 SFTP의 접속 결과가 달랐으므로 NAS 전체 장애와 외부 요청의 전달 문제를 구분해야 했습니다.
SYSTEM ARCHITECTURE

외부 요청이 거치는 두 공유기

SYSTEM FLOW

  1. External client

    외부에서 SFTP 접속 요청

    개인 사용 환경

  2. ISP router

    외부 요청을 개인 공유기로 전달

    복구 시 추가한 전달 설정

  3. Personal router

    NAS로 이어지는 전달 설정

    상위 공유기와 경로 연결

  4. NAS

    SFTP 연결 확인과 운영 점검

    개인 운영

SFTP 요청은 통신사 공유기와 개인 공유기를 차례로 거쳐 NAS에 도달합니다. Tailscale은 별도의 경로로 접속합니다.

ENGINEERING DECISIONS

접속 경로를 비교하고 포트포워딩을 수정했습니다

Separate access paths

Tailscale과 SFTP 접속 경로 비교

문제

외부 SFTP 접속이 실패해 개인 공유기 설정을 바꿨지만 해결되지 않았습니다.

선택

Tailscale은 연결됐기 때문에 SFTP 요청이 지나가는 경로를 따로 확인했습니다.

구현

웹 검색과 AI 대화로 이중 공유기 구조의 전달 경로를 검토했습니다. 외부 요청이 먼저 도착하는 통신사 공유기에 개인 공유기로 넘기는 설정이 빠져 있었습니다.

이유

두 방식의 접속 결과가 달라 NAS 자체와 SFTP 전달 경로를 나눠 살폈습니다.

결과

개인 공유기만 확인하던 데서 통신사 공유기의 설정까지 점검 범위를 넓혔습니다.

범위와 한계

패킷 캡처로 원인을 분석한 경험은 아닙니다. 실제 IP·계정·포트 설정값은 공개하지 않습니다.

Restore the complete path

두 공유기의 포트포워딩 설정

상위 공유기의 전달 설정이 없으면 요청이 개인 공유기까지 도달하지 못했습니다.

확인한 결과

끊겼던 외부 SFTP 접속을 복구했습니다.

범위와 한계

검증은 설정 변경 직후 외부 SFTP 재접속을 확인한 범위였습니다. 장기 가동률과 대용량 전송 안정성은 별도로 측정하지 않았습니다.

OUTCOME

이중 공유기의 전달 경로를 연결해 외부 SFTP 접속을 복구했습니다.

LIMITATIONS & LESSONS

한계와 배운 점

확인하지 못한 전송 중단 원인

Tailscale로 큰 파일을 보낼 때 전송이 멈춘 적도 있습니다. 이 문제는 원인을 확인하지 못했습니다.

앞으로 개선할 점

별도의 재현 조건과 전송 로그를 확보해 원인을 검증할 필요가 있습니다.
